# Геометрия Голдберга

Статус после слияния: это генератор dev preview клиента. В `server/app/world/` параллельно существует игровой генератор икосферы с другой версией и ID. Экспорт Голдберга пока не подключён к `UnitOfWork`; карты не взаимозаменяемы. Выбор общего формата и генератора зафиксирован в [задачах интеграции](protocol.md).

Генератор скопирован из [guillochon/goldberg-hexgrid](https://github.com/guillochon/goldberg-hexgrid/tree/51d110bb15e59c94afbf926729e6baf90f78fd6d).
Три исходных модуля в tools/vendor/goldberg_hexgrid сохранены без изменений; MIT-лицензия и происхождение находятся рядом. Вызов generate_goldberg_hex_sphere выполняется в tools/generate_world.py, вне браузера.

Этот вариант использует генератор GP(m,n) из указанного репозитория. Это замена первоначальному предложению реализовать Loop subdivision из статьи Daniel Sieger; не следует считать эти два алгоритма идентичными.

## Что изменилось

Вместо 25 вручную размещённых полигонов экспортируется замкнутая сетка GP(12,0):
1442 клетки, 12 пятиугольников, 1430 шестиугольников, 189 небольших связных чанков.

Исходная библиотека выдаёт центры и ближайших соседей. Адаптер строит SphericalVoronoi по её центрам, чтобы у соседних клеток были общие вершины и рёбра. Приблизительная отрисовка из upstream rendering.py не копировалась: независимый расчёт радиуса каждой плитки может оставлять щели. Исходный генератор при этом не изменён. Перед экспортом проверяются числа сторон, замкнутость и характеристика Эйлера; неподдерживаемые конфигурации отклоняются.

Клетки получают стабильные для данной версии/параметров cell_id, center, vertices, neighbors, surface и buildable. Четыре разнесённых пятиугольника выбираются как кандидаты посадки. Параметр --occupied задаёт занятость слотов по порядку: занятые имеют surface=landing, незанятые — surface=mountain и buildable=false. Остальные восемь пятиугольников остаются обычными клетками. Изменение числа игроков не меняет геометрию, соседство или ID.

Назначение слотов реальным пользователям, лобби и запрет взаимодействий/столкновения проверяет игровой сервер; генератор экспортирует только состояние площадок. На клиенте горы декоративные, исключены из выбора клетки. Нельзя считать генератор реализацией многопользовательского лобби.

## Графика и загрузка

- Серверные клетки имеют общие границы; нормали ориентированы наружу, без искусственных треугольных полос на каждой грани.
- Занятая пятиугольная площадка выделяется цветом и внутренней разметкой.
- Незанятая площадка отображается low-poly горой, когда её чанк попадает в область интереса.
- Полная оболочка тоже состоит из пяти-/шестиугольных граней, но это отдельный грубый GP(3,0), всего 92 грани, без ID, соседства и данных построек. Это визуальный фон, а не полная строительная сетка.
- shell поддерживает vertices и faces; старые radius/detail остаются совместимым резервным форматом.
- Все shell-данные входят в счётчик байтов snapshot.
- Полная карта хранится только в world/generated/goldberg.json. Vite dev middleware выдаёт ближайшие чанки с no-store; клиент не импортирует JSON или Python-генератор.
- При переключении камер используется та же позиция игрока и те же чанки.
- Preview остаётся отдельным режимом: локальное движение и HTTP-поток геометрии не заменяют production WebSocket, авторизацию и игровые проверки.

## Воспроизведение

Из корня (Linux / WSL):
```sh
python3 -m venv .venv-world
.venv-world/bin/pip install -r tools/requirements-world.txt
.venv-world/bin/python tools/generate_world.py
.venv-world/bin/python -m unittest discover -s tools -p 'test_*.py'
cd client
npm ci
npm run dev
```
Открыть http://localhost:5173/?fixture. Повторная генерация из client: npm run world:generate.
Можно выбрать --m, --n, --occupied и --output через Python CLI. Набор по умолчанию проверен тестами.
Для Windows допустим WORLD_PYTHON с путём Python из подготовленного окружения.
После подготовки окружения и npm-зависимостей генерация/preview работают без сети.
Файл generated и виртуальное окружение исключены из Git. Production npm run build не требует Python; production-сервер должен отдельно загрузить экспорт и выдавать его через согласованный протокол.

## Проверки

Python: числа граней, одинаковые рёбра соседей, наружный winding, радиус, симметричное соседство, связные чанки, стабильность ID, занятость 1/4 слотов, отделение оболочки.
JavaScript: обе ориентации вершин пяти-/шестиугольников, GPU dispose и прежние тесты кеша/движения/транспорта.
Браузер: обе камеры, четыре preview-вкладки; размер мира измеряется по реальным JSON-данным, а не синтетическому знаменателю.

## Поверхность в зависимости от камеры

От первого лица используется гладкая сфера с радиальными нормалями и процедурным материалом марсианской пыли (mars-surface.js). Текстура вычисляется в 3D-координатах: нет UV-шва, зависимости от CDN или дополнительных данных карты. Мелкое зерно ослабляется вдали, чтобы уменьшить мерцание.

В режиме сверху сохраняется многогранник Голдберга. Это два визуальных представления одного мира: radius, position, cell_id, область интереса и загруженные чанки не меняются. Вблизи обычные грани не рисуются; для выбора клетки используется их подразделённая сферическая геометрия. Посадочная разметка и контур выбранной клетки следуют кривизне сферы. Оба варианта геометрии освобождаются при выгрузке чанка.
