# Сохранение игрового состояния

FastAPI использует `BufferedGameWriter`. Тики и команды публикуют состояние
мира в памяти, передавая буферу уже отделённую копию. В буфере остаётся только
последняя версия каждого изменённого мира; промежуточные снимки заменяются.

Отдельный поток примерно раз в секунду сериализует накопленные миры и сохраняет
их одной транзакцией через собственное постоянное соединение SQLite. Интервал
отсчитывается после завершения предыдущего пакета. Для каждого мира сохраняется
полный JSON, а в `command_results` добавляются только ещё не записанные результаты.
Настройки WAL и synchronous не ослабляются.

Игровой ответ подтверждает принятие изменения в память, а не завершение записи
на диск. При аварийном завершении теряются изменения после последнего успешного
пакета: обычно около секунды, дольше при медленной или недоступной базе.
Снимок и его результаты команд записываются атомарно, чтобы повторные запросы
после восстановления соответствовали сохранённому состоянию.

Во время записи игра продолжает формировать следующий пакет. Завершённый пакет
не удаляет новые изменения. При ошибке последняя версия каждого мира остаётся
в буфере для повторной попытки, ошибка выводится в лог. При штатной остановке
FastAPI ждёт финального сохранения; ошибка финальной записи не скрывается.
Принудительное завершение процесса не позволяет гарантировать финальный сброс.

Регистрация, сессии, чат и история ИИ сохраняются прежним способом. Чат проверяет
идентификаторы ещё не записанных игровых команд, сохраняя общее пространство
идентификаторов запросов. `GameService(db)` вне FastAPI по умолчанию использует
синхронное сохранение; для буферизации нужно передать `persist=writer.submit`.

Буферизация не устраняет стоимость копирования мира в игровом потоке, чтения
сессий и рассылки WebSocket. История результатов команд пока входит в полный
снимок и растёт вместе с ним. Частичные изменения объектов и ограничение истории
могут стать отдельными оптимизациями после измерений.

## Воспроизводимый замер

```bash
PYTHONPATH=server .venv/bin/python tools/benchmark-persistence.py
# В том же Docker volume, что и сервер, без изменения рабочей базы:
docker compose exec -T server python - < tools/benchmark-persistence.py
```

Скрипт создаёт и удаляет отдельные временные базы: четыре игрока, 200 результатов
команд, 300 обновлений мира. Сравнивает прежнее синхронное сохранение с буфером,
сбрасываемым каждые 100 обновлений. Измеряет время вызова адаптера, число коммитов
и попыток вставки результатов команд. Это синтетический тест сохранений,
не измерение FPS, сетевой задержки или полного времени игрового тика.
