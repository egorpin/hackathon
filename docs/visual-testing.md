# Проверка производительности 3D

Этот протокол проверяет цель 60 FPS на ноутбуке с Intel Core i5-12500H и Intel Iris Xe. Запись результатов нужна отдельно для каждого режима качества и камеры. Скриншоты не приложены; результаты замеров пока не заявляются.

## Подготовка

1. Подключите ноутбук к питанию и выберите тот же профиль питания Windows, который будет использоваться на показе.
2. Закройте лишние приложения. Откройте браузер в отдельном чистом профиле, разверните окно на весь экран, оставьте масштаб страницы 100% и не открывайте DevTools.
3. В PowerShell из корня репозитория запустите backend:

   ```powershell
   $env:MARS_PLANET_RADIUS = '30'
   $env:MARS_PLANET_SUBDIVISIONS = '3'
   $env:DATA_DIR = (Join-Path (Resolve-Path .).Path 'data\bench-r30-s3')
   New-Item -ItemType Directory -Force -Path $env:DATA_DIR | Out-Null
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir server --host 127.0.0.1 --port 8000 --ws-max-size 4096
   ```

4. Во втором окне PowerShell запустите frontend:

   ```powershell
   Set-Location client
   npm run dev -- --host 127.0.0.1 --port 5173
   ```

5. Откройте `http://127.0.0.1:5173`, создайте игрока, затем дождитесь подключения и нажмите «Начать экспедицию». Для заполнения мира подключите ещё три отдельных браузерных профиля/сессии до старта. Используйте одинаковый viewport во всех запусках.

## Прогон

Для геометрического сравнения пройдите все шесть сочетаний `MARS_PLANET_RADIUS=30, 60, 90` метров и `MARS_PLANET_SUBDIVISIONS=3, 4`. Радиус меняет размер мира; subdivisions меняет плотность клеток и геометрии. Меняйте только эти параметры между прогонами, сохраняя остальные условия одинаковыми. Для каждого сочетания перезапустите backend с новым значением и **новым пустым `DATA_DIR`** (например, `data\bench-r60-s3`, `data\bench-r90-s4`); войдите четырьмя одинаково подготовленными участниками. Не открывайте другой вариант на существующей базе: сохранённый `map_version` должен совпадать. Сервер при несовпадении выдаёт явную ошибку и оставляет сохранение без изменений. Для возврата к сохранённому миру восстановите прежние `MARS_PLANET_RADIUS` и `MARS_PLANET_SUBDIVISIONS`.

Для каждого качества (`Низкое`, `Среднее`, `Высокое`) выполните шаги ниже. Переключатель покачивания камеры зафиксируйте в таблице; основной прогон делайте выключенным, затем повторите с включённым.

1. После загрузки мира дайте сцене прогреться 60 секунд.
2. Записывайте экран в течение всего прогона. HUD обновляет FPS и frame p95 по окну примерно в одну секунду; это не сводка за пять минут.
3. В течение пяти минут непрерывно двигайтесь по поверхности, вращайте обзор и проходите через область с чанками, постройками и другими игроками. Не держите вкладку в фоне.
4. Из записи выпишите все секундные HUD-сэмплы и посчитайте медиану и 5-й процентиль FPS, а также медиану и 95-й процентиль показаний секундного frame p95. Отдельно сохраните диапазон треугольников и вызовов отрисовки.
5. Повторите тот же маршрут с видом сверху и затем при включённом покачивании камеры.
6. Повторите полный прогон ещё два раза после перезагрузки страницы, чтобы проверить восстановление сохранённого качества.

## Критерий приёмки

- Цель — устойчивые примерно 60 FPS. Краткие отклонения из-за vSync и округления счётчика допустимы; оцените распределение секундных выборок, а не требуйте 60 FPS в каждом отдельном окне.
- Секундные frame p95 показания должны держаться около 16,7 мс или ниже. Записывайте медиану и 95-й процентиль этих секундных показаний; это не глобальный p95 всех кадров прогона.
- Условия одинаковы между режимами; укажите разрешение экрана, размер окна, качество, камеру, покачивание и число подключённых игроков.
- Если режим не проходит порог, запишите фактические значения и повторите его на низком качестве. Не подменяйте результат значением из `?fixture`: preview не измеряет реальный игровой мир и серверный поток.
