# Клиент: контракт для интеграции

Статус: клиентская реализация участника 1. **Предложение владельцам сервера и игровой логики, а не согласованный или уже реализованный серверный API.** Основной docs/protocol.md не изменён. Сервер в текущем репозитории содержит только health и статику.

## Запуск и границы

В client: npm ci, npm run dev. Обычный адрес подключается к /ws текущего origin с ws/wss. Сервер авторизует cookie и Origin; клиент не передаёт user_id/team_id в командах. Авторизация и её HTTP DTO должны быть предоставлены участником 2.

Для локальной проверки: http://localhost:5173/?fixture. Перед запуском выполните npm run world:generate из client (нужны Python-зависимости tools/requirements-world.txt). Генератор Голдберга скопирован из указанного пользователем репозитория; полная геометрия находится только в world/generated/goldberg.json, preview получает ближайшие чанки по HTTP. Production tree shaking исключает этот транспорт. Это проверка настоящей геометрии, но не реализация игрового сервера или мультиплеера. Подробности: [Геометрия Голдберга](goldberg.md).

Управление: WASD, мышь после клика по canvas, стрелки как резервный способ взгляда, Esc освобождает мышь, Tab меняет камеру, B отправляет строительство, E выдаёт building.selected для UI. При вводе в поля движение отключается. На HTTP LAN предусмотрен UUID через crypto.getRandomValues без обязательного randomUUID.

## DTO

Все позиции — массивы [x,y,z], центр сферы [0,0,0], метры. Heading — единичный касательный вектор направления вперёд в мировых координатах; pitch — радианы, [-1.45,1.45]. Right = heading × localUp. Камера не входит в input.

player.input.payload:
```json
{"seq":1,"axes":{"forward":1,"right":0},"heading":[0,0,-1],"pitch":0}
```
Оси [-1,1], диагональ нормализуется; частота 20 Гц. Сервер проверяет/нормализует направление, ограничивает ввод и скорость, рассчитывает столкновения. Клиентское предсказание ограничено 150 мс, положение корректируется каждым ответом. Это визуальное предсказание, не подтверждённые координаты. Локального достоверного решения столкновений нет — его предоставляет сервер участника 3.

world.snapshot (стандартная оболочка type, revision, payload):
```json
{
  "self_id":"player-1",
  "team_id":"team-a",
  "last_input_seq":0,
  "world":{
    "radius":100,"move_speed":4,"view_radius":24,"build_distance":7,
    "total_bytes":500000,"total_chunks":400,
    "shell":{"radius":99.7,"detail":3}
  },
  "players":[{"player_id":"player-1","position":[0,100,0],"heading":[0,0,-1]}],
  "buildings":[]
}
```
shell поддерживает грубую полигональную оболочку {radius, detail, vertices, faces}: faces — массивы индексов в vertices. В preview это отдельный GP(3,0), 92 грани без cell_id, соседства и игровых данных. Старый формат radius/detail остаётся резервным. Весь DTO оболочки включён в учёт состояния. Подробная карта GP(12,0) передаётся только чанками; генератор не входит в браузерный код.

world.delta.payload: players, buildings — массивы полных обновлённых записей; removed_players, removed_buildings — массивы ID. Отсутствующие поля означают отсутствие изменений. revision строго последователен **в потоке конкретного получателя**, иначе клиент закрывает соединение и ждёт новый snapshot. Сервер не должен использовать глобальные revision с пропусками вследствие фильтрации по командам/AOI.

Building: building_id, cell_id, building_type (drill / oxygen_generator / storage), position, optional interaction_point — массив [x,y,z]. Авторитетные расстояния/права/стоимость проверяет сервер. Здания удаляются из сцены при выгрузке их клетки; при повторной загрузке восстанавливаются из полученного состояния.

Chunk: chunk_id, cells[], optional rocks[]. Cell: cell_id, center [x,y,z], vertices [[x,y,z],...], neighbors [cell_id,...], surface, buildable. Вершины идут по границе выпуклой клетки. Клиент не создаёт ID/соседство и не предполагает шесть соседей. Rock: position, scale. Для камней используется InstancedMesh.

## Обязательное согласование ограничения байтов

Одного chunk.load недостаточно: размер нужно знать **до** получения тела. Реализованы дополнительные control-сообщения:

1. Перед первым snapshot сервер присылает world.offer с payload {total_bytes, byte_size}.
2. Клиент резервирует byte_size и отправляет world.accept с пустым payload. Только после этого сервер отправляет snapshot.
3. Перед каждой delta сервер отправляет world.offer {byte_size}, ждёт world.accept, затем отправляет delta. Одновременно допускается только одно предложение состояния.
4. Сервер предлагает разрешённый чанк через chunk.offer {chunk_id, byte_size, distance}. Клиент вытесняет старые загруженные данные и отправляет chunk.request с request_id; при нехватке места — chunk.release.
5. chunk.load.payload — непосредственно Chunk. Повторный offer существующего ID не запрашивается. Для новой версии чанка сначала нужен упорядоченный unload, затем offer.
6. chunk.release — уведомление об освобождении/отказе, не игровая мутация. Сервер прекращает будущие передачи ID. chunk.unload приходит только после уже отправленных load; сервер сериализует эту очередь. Не отправлять тело после отмены.
7. Смена камеры не инициирует ни запросов чанков, ни изменений серверной позиции. AOI вычисляет сервер только по игроку.

Размер: UTF-8 от JSON.stringify(payload), без оболочки сообщения и сжатия. Порядок ключей, экранирование Unicode и запись чисел должны совпадать на обеих сторонах; Python json.dumps по умолчанию этому НЕ эквивалентен. Владелец протокола должен обеспечить совместимую каноническую сериализацию и тестовые векторы до интеграции. Изменение total_bytes требует нового соединения/манифеста. Знаменатель включает уникальные записи статического мира, shell и динамики; его определяет сервер, клиент не вычисляет размер всей карты.

Учёт консервативный: текущий snapshot + загруженные чанки + зарезервированные входящие payload, включая delta. Старая и входящая запись могут кратковременно учитываться обе, что не занижает расход. GPU-буферы и вычисленные матрицы не являются отдельными сериализованными записями мира. Счётчик не измеряет общий JS heap/VRAM.

Цель 5%, жёсткая граница 10%; pinned state и входящие резервы нельзя вытеснить как обычный кеш. Кандидаты — старые, затем дальние чанки. Неиспользуемые чанки не сохраняются на диске. При переподключении сцена/кеш очищаются; неподтверждённые игровые команды повторяются с теми же request_id после snapshot. Сервер обязан дедуплицировать их. Chunk control-команды не повторяются через reconnect.

Гарантия до получения данных требует соблюдения offer/accept на сервере: браузерный WebSocket сам принимает незапрошенный frame в память до обработчика JS. Несогласованный серверный поток нельзя превратить в гарантию 10% лишь клиентским отказом постфактум. HTTP-данные мира сервер должен отдавать с Cache-Control: no-store.

## Интерфейс участнику 4

После старта доступен window.marsClient:
- events.on(name, callback) возвращает unsubscribe.
- command(type, payload) возвращает request_id либо undefined при отказе.
- toggleCamera(), dispose().

Внутренний Events также импортируется из client/src/net/events.js; UI можно подключить в main.js без global.

Исходящие события:
- connection.status: connecting / syncing / connected / reconnecting / unauthorized.
- world.ready: selfId, teamId, totalChunks.
- cache.stats: bytes, totalBytes, percent, chunks, queuedBytes, targetPercent, limitPercent.
- performance: fps, drawCalls, geometries, textures — измеренные значения.
- camera.changed: first / top.
- cell.selected: {cell, locallyAllowed}; предварительная подсказка, не разрешение сервера.
- building.selected: Building или null. UI показывает ресурсные действия и отправляет намерение.
- notice: текст ошибки/подсказки.
- action.result, inventory.updated, chat.message, agent.reply: payload сервера.

Команды:
- building.place {cell_id, building_type}
- resource.pickup / resource.deposit {building_id, resource, amount}
- resource.give {recipient_player_id, resource, amount}
- chat.send {text}
- agent.ask {agent_id, question}

Клиент не изменяет инвентарь/постройки оптимистически. UI участника 4 должен отображать подтверждения сервера и отказ по коду. main.js содержит только заменяемую панель управления сценой и диагностики; client/src/ui/ не создавался и не менялся.
