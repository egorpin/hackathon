# Статус после объединения веток — 31 октября 2026

В `main` объединены обновлённый `frontend` (`309ee3c`), `backend` (`4c065fb`) и `gameplay` (`1971fbc`). Backend и gameplay вошли fast-forward, свежий frontend — merge-коммитом, без конфликтов. Это объединение исходников, а не завершённая интеграция игры.

## Фактическая готовность

| Область | Реализовано | Осталось |
| --- | --- | --- |
| Клиент | Three.js-сцена, две камеры, управление, вход/регистрация, WebSocket `session.ready`/reconnect, кеш, HUD, dev preview Голдберга | Согласование DTO с ядром, игровой серверный поток, lobby, формы чата/ресурсов |
| Сервер | Авторизация, cookie-сессии, проверка Origin, `session.ready`, командный чат и дедупликация, SQLite WAL | Игровой dispatch, tick, snapshot/delta, выдача чанков, сохранение игры |
| Игровое ядро | Сферическая сетка, чанки/манифест, площадки, движение и коллизии, строительство, ресурсы, склад и кислород | Подключение к серверу, единая идемпотентность с чатом, сетевой поворот, resync |
| Сохранение игры | Сериализация `WorldState`, `UnitOfWork` с callback `persist` и откатом при ошибке | Адаптер SQLite и восстановление при запуске |
| Агенты | Заготовка каталога контента и требования | AgentService, знания, два характера, персональная память, UI |
| Запуск | Dockerfile, Compose, healthcheck, инструкции офлайн и backup | Проверка готовой игры на четырёх LAN-клиентах и после restart |

`server/app/main.py` обслуживает авторизацию и чат; остальные WebSocket-команды отвечают `NOT_IMPLEMENTED`. Production-клиент ожидает игровой snapshot; `?fixture` работает через Vite dev middleware. Тесты ядра не подтверждают мультиплеер или сохранение игры после перезапуска сервера. Расхождения ввода, snapshot, revision, типа склада и карты перечислены в [протоколе](protocol.md).

## Следующий порядок работы

1. Сервер: один `UnitOfWork` на мир, восстановление и атомарный `persist`, согласование полей с SQLite и общее пространство `request_id` игры и чата.
2. Сервер + игра: зачисление проверенного пользователя, `landing.select`, `world.start`, игровые команды, шаг 0,05 с и персонализированные snapshots. Определить resync и сетевую ориентацию.
3. Клиент + игра: согласовать ввод, snapshot, revision, тип склада и единую карту. Подключить существующую сцену и транспорт, добавить lobby и формы авторизации, чата и ресурсов.
4. Сервер + клиент: чанки по серверной позиции, бюджет уникальных байтов с оболочкой и очередью. Статический манифест сам по себе не обеспечивает предел 10%.
5. Агенты/UI: локальные знания и адаптация, персональное хранение и ответы, HUD из реального состояния.
6. [Приёмка](demo.md): четыре клиента, чужая команда, повторы, reconnect, restart, офлайн и резервное восстановление.

Роли: [клиент](plans/01-client.md), [сервер](plans/02-server.md), [игра](plans/03-game.md), [агенты/UI](plans/04-agents-ui.md). Сетевой API: [protocol.md](protocol.md); автономное ядро: [INTEGRATION.md](../world/INTEGRATION.md).

## Проверки

После слияния: 26 Python-тестов сервера/ядра, 15 JS-тестов клиента и 6 тестов генератора Голдберга прошли; production-сборка Vite 6.4.5 успешна. Есть предупреждения о deprecated alias AnyIO и JS-бандле больше 500 kB; ошибок тестов или сборки нет. Браузерные показатели из клиентского отчёта при этом слиянии не перепроверялись.

Из корня в PowerShell: `.venv/Scripts/python -m pytest -q`. Сборка клиента: из `client` выполнить `npm run build` после установки зависимостей через `npm ci`. Окружение: [docker.md](docker.md).

Docker, LAN на четырёх ноутбуках и сквозное игровое демо требуют отдельной проверки; модульные тесты и сборка клиента их не заменяют.
