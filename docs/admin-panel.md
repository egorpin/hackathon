# Панель администратора

Панель запускается вместе с FastAPI и открывается по `/admin` на адресе игры.
Отдельный процесс, порт и сборка панели не нужны. Vite (dev) и nginx (production)
проксируют этот путь в сервер.

## Доступ

Задайте `MARS_ADMIN_TOKEN` (не менее 24 символов) в окружении сервера или `.env`
для Docker Compose. Перезапустите сервер после изменения ключа.
Если значение не задано, сервер создаёт `DATA_DIR/admin.key` с правами `0600`
и повторно использует его при следующих запусках. В Docker ключ находится в
постоянном volume; получить его можно командой:

```sh
docker compose exec server cat /data/admin.key
# Для production:
docker compose -f compose.prod.yaml exec server cat /data/admin.key
```

Введите ключ на странице `/admin`. Авторизация игрока не даёт административных
прав. Ключ передаётся в Authorization, хранится только в памяти вкладки и
удаляется кнопкой «Отключиться» или перезагрузкой страницы. Изменяющие запросы
проверяют Origin по правилам игрового сервера. API не кешируется.

## Возможности

- Все активные игровые WebSocket-подключения, включая лобби и отдельные вкладки
  одного игрока: FPS, ping, P95 времени кадра, draw calls, треугольники,
  фоновая вкладка и возраст последнего отчёта.
- Средние FPS/ping только по свежим данным активных вкладок; время шага симуляции,
  uptime сервера и занятость ИИ. Нет данных и устаревшие отчёты отмечены явно.
- Выбор мира, пауза симуляции, кислород (0–100%) и ресурсы команд с проверкой
  вместимости складов. Пауза останавливает тики, но оставляет чат и команды доступными.
- Создание, удаление и настройка профилей ИИ-персонажей: имя, инструкции,
  температура и включение. Один выбранный персонаж отвечает в существующем
  интерфейсе помощника. История разделена по миру, игроку и персонажу.
  Настройка поведения действует со следующего запроса, без перезапуска сервера.
- Программы существующих роверов: сохранение, запуск с начала, остановка.
  Используется тот же безопасный язык и парсер, что в игровом интерфейсе.

Настройки и состояние сохраняются штатной транзакцией мира в SQLite. Конфликты
параллельного редактирования настроек / программ возвращают 409. Панель не
перезагружает формы автоматически: для актуального состояния используйте
«Загрузить настройки». Неизменённые кислород и ресурсы не отправляются при
сохранении профилей, чтобы не откатывать прогресс симуляции.

Это редактор состояния существующих миров и поведения существующих типов
агентов. Геометрия планеты (радиус и детализация) остаётся конфигурацией запуска;
панель не регенерирует карту и не добавляет новый тип физических NPC.

## Протокол

Клиент раз в 2 секунды отправляет `telemetry.report` по авторизованному `/ws`:
`{fps, frameP95, drawCalls, triangles, hidden}`. Числовые значения могут быть null.
Сервер ограничивает отчёты одним за 0.8 секунды и отвечает `telemetry.ping` с nonce.
Клиент немедленно возвращает `telemetry.pong` с тем же nonce. Сервер измеряет RTT
своими монотонными часами. FPS и рендер-метрики сообщаются клиентом; RTT включает
очереди WebSocket и обработку браузером. Метрики живут только до отключения.

Административные endpoints требуют `Authorization: Bearer <ключ>`:

- `GET /api/admin/overview` — все подключения, миры, метрики сервера.
- `GET /api/admin/worlds/{id}` — редактируемые настройки и список роверов.
- `PUT /api/admin/worlds/{id}` — version, paused, characters, active_character;
  опционально oxygen_percent и team_storage.
- `PUT /api/admin/worlds/{id}/rovers/{rover_id}` — expected_revision, program,
  action (`save`, `start`, `stop`).

Административные инструкции не попадают в игровые snapshot/delta. Ответы
`/api/agent/messages` и `/api/agent/ask` дополнительно содержат публичные
`character: {id, name}` для отображения выбранного персонажа.
