# Проверка и показ

## Что можно проверить сейчас

- Сервер: `.venv/Scripts/python -m pytest -q` из корня проверяет авторизацию, Origin, чат, повторы и игровое ядро отдельно.
- Клиент: из `client` выполнить `npm ci`, `npm test`, `npm run build`.
- Геометрия и камеры: подготовить экспорт по [goldberg.md](goldberg.md), запустить `npm run dev` и открыть `http://localhost:5173/?fixture`. WASD — движение, мышь/стрелки — взгляд, Tab — камера. Это локальная проверка, четыре preview-вкладки не являются мультиплеером.
- Обычный production URL пока не получает игровой snapshot от сервера. Формы входа и игровые экраны ещё требуют интеграции; healthcheck проверяет только доступность сервера/БД.

Состояние модулей и блокирующие расхождения: [status.md](status.md), [protocol.md](protocol.md). Запуск и backup: [docker.md](docker.md).

## Целевой сквозной сценарий после интеграции

Следующие шаги — критерии приёмки будущего демо, пока не выполненные целиком.

1. До отключения WAN собрать образ, подготовить локальные ассеты, сохранить образ и резервную копию volume. Записать LAN-IP; четыре ноутбука находятся в одной сети.
2. Отключить WAN, сохранив LAN. Запустить `docker compose up -d --no-build --pull never`; проверить `/api/health` с другого ноутбука.
3. Войти четырьмя пользователями одной команды. Показать движение от первого лица на сфере и других игроков.
4. Переключить камеру наверх: пяти-/шестиугольники видны только в прежней области; вернуться обратно.
5. Построить бур, добыть руду, перенести на склад, передать часть второму игроку, запустить генератор кислорода. Показать отказ слишком далёкого действия.
6. Задать инженеру вопрос дважды: ответ меняется с учётом памяти. Второй пользователь получает отдельное объяснение. Показать планетолога.
7. Пройти по планете: чанки меняются, HUD показывает реальные байты ≤10%. Камера сверху не расширяет загрузку.
8. Переподключиться, проверить инвентарь, постройки и память. Перезапустить контейнер и повторить проверку; допускается небольшой откат позиции, но не ресурсов.

Перед показом дополнительно: повтор request_id не меняет результат дважды; из двух конкурентных построек на одной клетке успешна одна; тестовая вторая команда не видит приватные данные и не использует чужой склад; чужой Origin/нет сессии отклоняются.

Участник 1 демонстрирует камеры/кеш, 2 — LAN/перезапуск, 3 — ресурсный цикл, 4 — агентов и ведёт показ. После 4:30 новые функции не добавлять.
