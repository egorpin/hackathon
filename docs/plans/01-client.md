# Участник 1 — клиент и 3D

Инструкция агента: [agents_client.md](../../agents_client.md).
Владение: `client/src/scene/`, `client/src/net/`, клиентский кеш, точка входа и сборка клиента. UI согласовывать с участником 4.

| Время | Действия и результат | Проверка / передача |
| --- | --- | --- |
| 0:00–0:20 | С участниками 2 и 3 согласовать координаты сферы, ориентацию, input, snapshot, cell_id и размеры чанков. Создать сцену и сетевой адаптер. | Клиент принимает согласованный тестовый snapshot без собственной модели протокола. |
| 0:20–1:00 | Low-poly оболочка, первое лицо, локальная вертикаль, касательное движение, Pointer Lock. Отправка намерений и интерполяция других игроков. | Два браузера видят движение друг друга; сервер корректирует позицию. |
| 1:00–2:00 | Визуал пяти- и шестиугольников из серверной геометрии, выбор клетки, preview бура. Камера сверху, загрузка/выгрузка чанков. | Четыре игрока; переключение камеры не меняет позицию, область интереса и доступные здания. |
| 2:00–3:00 | Визуализировать бур, склад, генератор, точки взаимодействия; подключить команды UI участника 4. | Руда переносится по серверным ответам; недопустимое строительство показывает отказ. |
| 3:00–4:00 | Учёт оболочки, активных чанков, кеша и входящей очереди по уникальным сериализованным байтам. Рабочий бюджет 5%, предел 10%; eviction до приёма данных, GPU dispose, InstancedMesh. | Длительная прогулка не превышает лимит; отдать участнику 4 реальные счётчики HUD. |
| 4:00–4:30 | Пройти LAN/офлайн-тест на четырёх ноутбуках, проверить reconnect и оба режима камеры. | Нет CDN, внешних шрифтов и полной карты в сборке/IndexedDB/service worker. |
| 4:30–5:00 | Заморозить функции, устранить критические дефекты, репетиция. | Стабильный клиент в финальном Docker-образе. |

Зависимости: участник 3 предоставляет геометрию и правила движения; участник 2 — протокол, авторизацию и поток чанков; участник 4 — UI. Пока сервер не готов, использовать небольшой fixture с теми же полями, явно отделённый от рабочего транспорта.

Готово: оба режима камеры, непрерывное движение по сфере, другие игроки, строительство и перенос через сервер, корректная выгрузка и измеряемые ≤10%. Цель — 60 FPS; фиксировать фактический результат на ноутбуках.

Если к 1:00 два клиента не видят друг друга, вместе с участником 2 исправить интеграцию. Упрощать модели и эффекты, сохраняя сферу, камеры и бюджет данных. Третье лицо — после демо.
