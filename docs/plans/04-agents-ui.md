# Участник 4 — локальные агенты, UI и показ

## Статус после слияния 31 октября 2026

Клиент уже предоставляет диагностический HUD и `window.marsClient`; сервер — HTTP-авторизацию и командный чат. AgentService, знания, персональная память и продуктовые формы пока отсутствуют. Следующий шаг: формы входа/чата и lobby, UI ресурсов по согласованным DTO; затем два локальных агента и сохранение памяти.

Общий [статус](../status.md), [расхождения протоколов](../protocol.md), [контракт ядра](../../world/INTEGRATION.md) и [клиента](../client-integration.md). Ниже — исходный таймбокс и критерии приёмки, не отметки о выполнении.

Инструкция агента: [agents_agents_ui.md](../../agents_agents_ui.md).
Владение: `server/app/agents/`, `content/`, `client/src/ui/`, `docs/demo.md`. Точку входа клиента согласовывать с участником 1, storage — с участником 2.

| Время | Действия и результат | Проверка / передача |
| --- | --- | --- |
| 0:00–0:20 | Согласовать answer, agent.ask/reply, chat, HUD и ключ памяти. Описать короткий сценарий показа. | Состояние UI имеет единый вход из net; память индексируется world_id/user_id/agent_id. |
| 0:20–1:00 | Форма входа, статусы соединения, инструкции управления, каркас инвентаря и чата. Локальные характеры инженера и планетолога. | UI показывает загрузку/ошибку и не подменяет результат сервера. |
| 1:00–2:00 | Выбор здания и подтверждение, ошибки action.result; локальная база знаний и поиск тем инженера. | Инженер отвечает офлайн по вопросу и состоянию игры; строительство связано с выбранной клеткой. |
| 2:00–3:00 | Инвентарь, перенос и передача ресурсов, кислород/общая цель, командный чат. Адаптация инженера к пройденным темам и ошибкам. | Первый вопрос даёт объяснение, повторный — задачу/расчёт; полный ресурсный цикл понятен из UI. |
| 3:00–4:00 | Второй агент, сохранение истории и персональной памяти, HUD чанков и процентов из реальных счётчиков клиента. | Два игрока получают независимые ответы; память переживает reconnect; HUD учитывает очередь и оболочку. |
| 4:00–4:30 | Пройти сценарий на четырёх ноутбуках без интернета, проверить приватность и сообщения ошибок. | Личные agent.reply не рассылаются команде; чат команды не попадает другой команде. |
| 4:30–5:00 | Финальная репетиция, короткие реплики демонстратора, резервный сценарий без LLM. | Показ укладывается в отведённое время, каждый обязательный пункт виден жюри. |

Зависимости: участник 3 даёт рецепты/состояние, участник 2 — авторизованный контекст и storage, участник 1 — события выбора клетки и измерения кеша. Не копировать игровые правила в UI; показывать доступные действия и обрабатывать отказ сервера.

Готово: два разных характера, локальный поиск + правила адаптации, отдельная сохранённая память, рабочий чат/HUD, измеряемый лимит мира и воспроизводимое демо. Неизвестный вопрос получает честный ответ об отсутствии знания и предложение подходящей темы.

LLM подключать только за AgentService, вне игрового шага и после обязательного варианта без GPU. При нехватке времени сократить оформление и объём знаний, сохранив двух агентов, адаптацию и независимость памяти.
