# Windows 11: единый адрес https://mars.local:8443

Проект находится в WSL серверного ноутбука. Docker Desktop запускает игру,
Windows-утилита `mars-mdns.py` объявляет имя `mars.local` в Wi-Fi LAN. На клиентах
не нужны Docker, WSL и Python. Все компьютеры, включая сервер, открывают один URL.
`localhost` остаётся резервным адресом для серверного браузера.

## Подготовка серверного ноутбука

Подготовка выполняется заранее, пока есть интернет. Нужны Docker Desktop с
интеграцией нужного WSL-дистрибутива, Python 3.10+ **для Windows** с командой `py`,
а в WSL — Python 3, OpenSSL и работающий `docker compose`.

Откройте папку проекта через Проводник, например
`\\wsl.localhost\Ubuntu\home\USER\projects\hackathon`, затем запустите из Windows
PowerShell (замените путь своим):

```powershell
& '\\wsl.localhost\Ubuntu\home\USER\projects\hackathon\start-server.cmd' -Prepare
```

Скрипт определяет дистрибутив и Linux-путь из UNC-пути. Их можно задать явно:

```powershell
.\start-server.cmd -Distro Ubuntu -ProjectPath /home/USER/projects/hackathon -Prepare
```

Подготовка создаёт отдельное Windows-окружение
`%LOCALAPPDATA%\MarsColony\mdns`, устанавливает `zeroconf`, копирует утилиту,
выпускает сертификат для `mars.local` с сохранением существующего CA и собирает
production Docker-образы. Повторяйте `-Prepare` после обновления кода утилиты.
Перевыпуск сертификата не требует повторной установки того же CA.

Также создаётся папка `%LOCALAPPDATA%\MarsColony\client`:

```text
client/
  start-client.cmd
  ca.crt
  windows/start-client.ps1
```

Скопируйте **эту папку целиком** на каждый клиент. Приватных ключей в ней нет.
На сервере тоже используйте её для первоначальной установки CA. На каждом
компьютере в Windows PowerShell из папки `client` выполните один раз:

```powershell
.\start-client.cmd -TrustCertificate -InstallOnly
```

Это явная установка CA в `CurrentUser\Root`, без прав администратора. Скрипт
выводит SHA256 сертификата: сравните его с серверным экземпляром при передаче.
Обычный запуск сертификаты не устанавливает. После установки перезапустите браузер.
Для демонстрации используйте Edge/Chrome; Firefox может требовать отдельного
импорта CA в своё хранилище.

**Только на сервере**, из Windows PowerShell от администратора под тем же
пользователем выполните:

```powershell
& '\\wsl.localhost\Ubuntu\home\USER\projects\hackathon\windows\setup-server-firewall.ps1'
```

Скрипт создаёт два входящих LAN-правила: TCP 8443 для игры и UDP 5353 для
mDNS. Правила действуют и для Public-профиля, который Windows
может назначить телефонной точке доступа; удалённые адреса ограничены LocalSubnet.
Firewall не отключается, настройки WSL, `hosts` и системные службы не меняются.
Правила добавляются только при явном запуске этого отдельного скрипта.

## Запуск демонстрации

1. Подключите все компьютеры к одной точке доступа. Сохраните LAN, отключив
   мобильные данные и другие источники интернета телефона и компьютеров.
2. На сервере запустите `start-server.cmd` из того же UNC-пути, **без `-Prepare`**.
   Он запускает готовые Docker-образы через WSL с `--no-build --pull never`,
   затем запускает Windows mDNS-утилиту и открывает `https://mars.local:8443`.
   Контейнеры пересоздаются, чтобы Nginx получил актуальные файлы сертификата;
   SQLite volume сохраняется. Повторный запуск прерывает текущие соединения игроков.
3. **Не закрывайте серверное окно:** оно обслуживает mDNS. Ctrl+C завершает
   объявление и снимает записи; игровые контейнеры продолжают работать.
4. На каждом клиенте запустите `start-client.cmd`. Он проверит разрешение имени
   средствами Windows, выполнит HTTPS-запрос `/api/health` с проверкой цепочки
   и имени сертификата и откроет браузер. Прокси для проверки не используется.

Все действия обычного запуска выполняются локально. Зависимости не скачиваются,
сертификаты не перевыпускаются. Игра использует тот же адрес для API и WSS.

Если включено несколько физических адаптеров, задайте нужный явно:

```powershell
.\start-server.cmd -Distro Ubuntu -ProjectPath /home/USER/projects/hackathon -Interface 'Wi-Fi'
```

Список адаптеров можно посмотреть без изменения настроек:

```powershell
& "$env:LOCALAPPDATA\MarsColony\mdns\Scripts\python.exe" "$env:LOCALAPPDATA\MarsColony\mdns\mars-mdns.py" --list-interfaces
```

Утилита учитывает только активные физические адаптеры Windows, исключая WSL,
Docker и VPN. Каждые несколько секунд проверяет адрес; при смене IP снимает
старое объявление и публикует новое, при отключении ждёт восстановления сети.
Сертификат остаётся прежним. При смене Wi-Fi на Ethernet с заданным `-Interface`
перезапустите утилиту с новым именем адаптера. DNS-кеши клиентов обновляются
не мгновенно; при необходимости повторите клиентский запуск спустя 30 секунд.

Для другого порта передавайте одинаковый `-Port 9443` серверному, клиентскому
и firewall-скрипту. Этот параметр серверного запуска имеет приоритет над `.env`.
Для проверки без открытия браузера предусмотрен `-NoBrowser`.

## Ограничения и диагностика

В одной LAN должен быть один сервер Mars Colony. Утилита не переименовывает имя
при конфликте регистрации службы, а сообщает ошибку. Не используйте одновременно
другой ответчик с именем `mars.local`.

На клиенте выполните `Test-NetConnection mars.local -Port 8443`. Если имя не
находится, проверьте серверное окно, выбор адаптера, UDP 5353, multicast и правила
firewall. Если подключение по IP работает, а по имени нет, проблема в обнаружении,
а не в сертификате. Самостоятельно установленные `hosts`-записи могут мешать
обновлению IP; эти скрипты файл `hosts` не изменяют.

Телефон должен разрешать общение клиентов и multicast. Если он фильтрует mDNS,
доступен ручной резервный вариант из [инструкции HTTPS](https-lan.md): имя из
сертификата связывается с текущим IP через `hosts`. Если устройства изолированы,
понадобится другая сеть. На целевых Windows-компьютерах необходимо проверить
прохождение multicast и разрешение `.local` штатным резолвером и браузером.

Остановка игры: в WSL из папки проекта выполните
`docker compose -f compose.https.yaml stop`. Для удаления добавленных firewall-правил
на сервере: `Get-NetFirewallRule -Group 'Mars Colony' | Remove-NetFirewallRule`
из административного PowerShell. Окружение утилиты можно удалить из
`%LOCALAPPDATA%\MarsColony\mdns` после её остановки; служба Windows не устанавливается.

## Проверки разработки

`python -m pytest tools/test_mars_mdns.py` с зависимостями `tools/requirements-mdns.txt`
проверяет смену IP, потерю сети, снятие записей и выбор адаптера. Сам Windows-запуск,
установка CA и настройка firewall должны проверяться на серверном ноутбуке.
